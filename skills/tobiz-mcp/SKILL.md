# TOBIZ через MCP: как работать и на чём спотыкаются

Сервер `tobiz-mcp` даёт доступ к сайтам конструктора TOBIZ: 53 инструмента `tobiz_*`. Публичного
API у конструктора нет — сервер работает с внутренними эндпоинтами редактора и панели, поэтому
часть правил ниже неочевидна и выведена опытным путём.

## Справочники (читай до того, как гадать)

Разбор вендорских исходников и внутренних эндпоинтов лежит рядом со скилом. **Устанавливай скил
копированием папки** — установка по прямой ссылке на `SKILL.md` тянет только сам файл, без
справочников:

```bash
git clone https://github.com/raydev-ru/tobiz-mcp.git /tmp/tobiz-mcp
cp -r /tmp/tobiz-mcp/skills/tobiz-mcp ~/.hermes/skills/
```

| Файл | Что внутри |
| --- | --- |
| `references/block-catalog.md` | все 28 категорий и 162 типа блоков: `type_id`, название, для чего — чтобы выбрать блок под задачу, а не перебирать наугад |
| `references/block-engine.md` | как устроен движок: `values`/`cache`, каркас секции, общие поля (фон, отступы, ширина, срез, «плашка под текстом»), изображения, массивы, список всех рендереров вендора |
| `references/components.md` | кнопки (все поля, пресеты, `radius` в em, автоконтраст текста), формы (17 типов полей, маски, капча, попапы, «Спасибо»), меню (уровни через `level`, бургер, dropdown-переменные), карты, лого/телефоны/соцсети, видео, таймеры, quiz, калькулятор |
| `references/control-registry.md` | как получить галочки и списки любого блока; контрольный аудит каталога `432879` |
| `references/panel-api.md` | внутренние эндпоинты панели и редактора, формат ответов, коды ошибок, где лежат пресеты шрифтов и стили сайта |

## Порядок работы

1. При первом подключении запусти `tobiz_onboarding_check`. Для личной тестовой установки достаточно
   `ready=true`; перед передачей MCP другому пользователю требуется `distribution_ready=true`.
2. `tobiz_list_projects` → `project_id` (если проект один, его можно не указывать).
3. `tobiz_list_pages` → `page_id` нужной страницы.
4. Понять, что уже есть: `tobiz_page_summary` (компактно) или `tobiz_list_blocks`.
5. Найти подходящий тип блока: `tobiz_search_blocks` (русский поиск по названию/описанию) →
   `tobiz_describe_block` (схема полей: имена, русские подписи, значения по умолчанию).
6. Правки: `tobiz_add_block` / `tobiz_update_block` / `tobiz_delete_block` / `tobiz_move_block`.
   Всё это живёт **в черновике** в памяти сервера.
7. Записать на сайт: `tobiz_save_page` — рендерит HTML блоков и отправляет `SaveBlocks`.
8. Проверить результат по **публичной вёрстке**: `tobiz_audit_page` сразу делает desktop/mobile
   снимки, читает computed styles и проверяет формы, кнопки, попапы, изображения и переполнение.

## Безопасный протокол сохранения

1. Перед первой правкой всегда перечитай страницу через `tobiz_page_summary` или
   `tobiz_page_info`. Чистый локальный черновик обновляется из TOBIZ, а несохранённый сохраняется.
2. Не продолжай сохранение при `REMOTE_BLOCK_CONFLICT`: пользователь изменил страницу в редакторе
   после чтения. Перечитай страницу и повторно примени только нужные правки.
3. `tobiz_save_page` автоматически создаёт локальную резервную копию текущей серверной версии.
   После значимой записи проверь наличие копии через `tobiz_list_page_backups`.
4. Восстановление выполняй только через `tobiz_restore_page_backup(confirm=true)`. Перед ним MCP
   создаёт дополнительную страховочную копию текущего состояния.
5. Для клиентской или общей установки включай `TOBIZ_REQUIRE_PROJECT_ALLOWLIST=true` и обязательно
   задавай `TOBIZ_ALLOWED_PROJECT_IDS`. Пустой белый список в строгом режиме должен блокировать
   любые операции с проектами.
6. Перед передачей страницы человеку запускай `tobiz_editor_roundtrip_check`; результат должен
   содержать `editor_safe=true` и `would_save=false`.

## Что пишет сразу, а что нет

| Действие | Когда попадает на сайт |
| --- | --- |
| правки блоков (`add`/`update`/`delete`/`move`) | только после `tobiz_save_page` |
| `tobiz_save_page` | сразу (рендер + `SaveBlocks`) |
| `tobiz_update_page` (SEO, название, slug, og:image, доступ) | сразу |
| `tobiz_copy_page`, `tobiz_delete_page` | сразу (`delete_page` требует `confirm=true`) |
| `tobiz_upload_image`, `tobiz_set_block_image` | сразу (файл загружается на сервер) |
| статьи и товары (`create`/`update`/`delete`, загрузка фото) | сразу, без `tobiz_save_page` |
| глобальные стили (`tobiz_update_site_styles`) | черновик; применяются через `tobiz_save_page` |

## Грабли (каждая проверена на живом сайте)

1. **Без `tobiz_save_page` на сайте ничего не изменится.** Сервер хранит HTML блока, а не «поля»,
   поэтому сохранение само рендерит HTML шаблонами вендора. Если рендер не удался — сохранение
   падает с `RENDER_FAILED`, и это лучше, чем записать пустой блок.
2. **Идентификаторы передавай как удобно** — числа принимаются (`project_id: 432549`) наравне
   со строками. Но **тип блока — это `type_id`**, а не `block_type_id`: при опечатке вернётся
   `UNKNOWN_TYPE` с пустым значением, что легко принять за «блока нет в сборке».
3. **`select`-поля принимают строку** (`mode: "3"`, а не `3`) — иначе `BAD_ARGUMENT`.
4. **Массивы контента (`arr1`, `arr2`, `menu1`, `form1`) задаются целиком.** Сколько элементов
   передал — столько и останется; чтобы удалить пункт, передай укороченный список.
5. **Дефолты вендора надо перезаписывать.** Новый блок приходит с демо-текстами («Плиточные
   работы», «Тариф М», «Замеры с ювелирной точностью»), демо-картинками и телефоном
   `+7 800 333 22 33`. Они живут в тех же полях, что и рабочий контент, и попадают на сайт,
   если их не тронуть. После сборки страницы полезно свериться с публичной вёрсткой на предмет
   таких остатков.
6. **`tobiz_upload_image` требует `block_id` реального блока этой страницы**: без него конструктор
   отвечает «Изображение не загружено! #2», с посторонним id — `#3`. Сервис сам отсекает вызов
   без `block_id`. Картинки, доступные для страницы, можно подсмотреть в
   `tobiz_page_info` → `page_image_options`.
7. **Параметры страницы читай через `tobiz_page_info`**, а не по ответу редактора:
   `window.tobiz` может отдавать устаревшие значения (мы на этом уже попались).
8. **`tobiz_update_page` отправляет форму целиком** — так устроена панель (`action=edit_page`).
   Инструмент сам делает «прочитал → подменил → отправил → перечитал и сверил», а недоведённые
   поля возвращает в `mismatched`. Если что-то не применилось — смотри `mismatched`, а не верь
   `status: OK`.
9. **SEO дублируется в `SaveBlocks`**: после правки SEO через `update_page` не сохраняй страницу
   из старого черновика — сначала перечитай (`page_summary`/`page_info`).
10. **Радиус кнопок задаётся полем `radius` в `em`**, и рендерер выводит его инлайн-стилем
    (`border-radius: <radius>em`) — инлайн перекрывает вендорское правило
    `.btn1.surround{border-radius:2px}`. Поэтому считай значение от шрифта кнопки:
    `radius = 7 / font_size_px` (0.35 при 20px, 0.389 при 18px, 0.412 при 17px дают ровно 7px).
    Пресет `style` тоже задаёт радиус, но поле `radius` его перекрывает. Проверка — вычисленный
    `border-radius` в браузере, а не «на глаз».
11. **Цвет текста кнопок внутри форм полем не задаётся** — работает `var(--autocontrast-text-color)`:
    светлый фон кнопки → тёмный текст, тёмный → белый. Поэтому тёмно-зелёная кнопка получает белый
    текст сама, а вендорские жёлтая и оранжевая — чёрный. Меняешь фон кнопки — перепроверь
    вычисленный `color`.
12. **Меняй модель блока и перерисовывай, а не подпирай CSS.** Блок «Пользовательский код»
    (type 163) со своими правилами и `!important` — крайнее средство: он расходится с настройками
    в редакторе (в полях останется одно, на сайте другое) и легко забывается. Правка полей +
    `tobiz_save_page` даёт тот же результат честно.
13. **`?v=<число>` в публичном URL — это id страницы.** Не добавляй свои query-параметры с `v`
    (`?v=2` отдаёт 404). Для обхода кеша подойдут любые другие параметры.
14. **Flex-блоки `1600` сохраняются через cache конструктора.** Рендер MCP должен вызывать
    вендорские `FlexibleTools.renderFlexblocks` и `renderStyles`, чтобы в `cache` попадали
    реальные `flexblock_wrapper` и CSS, а не только изменённые `values`. Если тип архивный или
    у него нет шаблона, меняй только значения верхнего уровня и проверяй результат.
15. **Каталог и видео — только штатными блоками.** Для каталога `type_id=130` включай штатное
    поле показа кнопок и штатную `popup_form`; ошибка `R is not defined` означает, что в
    MCP-рантайме не проброшен `R = window.tobiz.isValidValue`. Для плитки из четырёх видео в
    актуальном каталоге блок с видимым номером «705. Два видео с подписями» имеет фактический
    `type_id=3050` (видимый номер и `type_id` не обязаны совпадать). Сначала обнови assets и
    найди блок через `tobiz_search_blocks`, не угадывай идентификатор. Ошибка
    `O is not defined` лечится в рантайме алиасом `O = window.tobiz`, а не самописным HTML.
16. **Flex поддерживает девять штатных элементов.** Для `1600` используй `text`, `html`,
    `mdicon`, `figure`, `hint`, `image`, `video`, `form` и `btn`. Стили хранятся по режимам
    `l/m/s/xs/xxs`; не заменяй элементы внешним HTML/CSS, если нужный элемент есть в flex.
17. **Перед массовой работой проверяй каталог.** `tobiz_audit_catalog` рендерит vendor-default,
    реальные серверные значения, оба состояния каждой галочки и все варианты каждого `select`.
    Полный реестр подписей и имен полей читай через `tobiz_block_controls`: `control_type=checkbox`
    показывает только галочки, `interactive` - галочки и списки, `all` - все настройки блока.
18. **Работай на отдельном сайте.** Правки блоков и SEO уходят на прод-страницу сразу;
    для экспериментов — `TOBIZ_READ_ONLY=1` и отдельный проект.
19. **Статьи и товары - отдельные редакторы.** Они не используют черновик страницы и не требуют
    `tobiz_save_page`. В статьях `description` и `short_description` - HTML CKEditor; видео
    вставляется штатным `iframe`. У товара ссылки на видео лежат в `video1`-`video3`.
20. **Загрузка фото товара отличается от статьи.** Статья отправляет
    `action=upload_article_image, entity=article`, товар - `action=upload_image, entity=image`.
    Подмена `entity=image` на `item` дает ошибку «Сущность не корректная».
21. **Сортировка изображений требует полный порядок.** Передавай в `sort_article_images` или
    `sort_product_images` все текущие `image_ids` ровно по одному разу. MCP проверяет набор до
    записи, затем вызывает штатные `sort_article_images`/`sort_images`.
22. **Варианты товара - это offers.** Создание привязано к `product_id`; редактируются `title`,
    `vendor_code`, `price`, `quantity`, `image_id`. Фото варианта выбирается только из галереи
    родительского товара.
23. **Стили сайта правь через `page_config`.** `tobiz_update_site_styles` меняет штатные поля
    `text_*`, `title_*`, `menu_*`, `btn_bg`, `btn_bg_hover`. При `apply_to_all_pages=true`
    сохраняй каждую возвращенную страницу через `tobiz_save_page`.

## Красивый UI: как получить и с чего начать

Стиль задаёт не вёрстка, а решения: один оффер, один целевой действие, одна типографическая шкала.
Для этого скил работает в паре с **`tobiz-design`**. В нем находятся проверенные визуальные
системы, 17 изученных TOBIZ-референсов и рецепты обычных блоков из тестового проекта `432879`.

Порядок применения внутри TOBIZ:

1. **Структура и копирайт — по `tobiz-design`** (оффер, заголовки, доказательства, CTA,
   SEO-блок). Это дешевле и важнее цветов.
2. **Секции — из каталога блоков.** Не подгоняй неподходящий блок: в `references/block-catalog.md`
   под каждую задачу есть 3–5 вариантов (обложки, преимущества, тарифы, отзывы, форма, подвал).
3. **Визуальные правила — полями блоков, а не CSS:** фон и отступы (`bg*`, `padd_top`/`padd_bottom`),
   ширина контейнера (`inner_width`), скругление и цвета кнопок (`style`/`radius`, `color`, `text_color`),
   радиус и границы карточек — в самом блоке; шрифты — пресетами сайта (`/json/stylesFontsPresets.json`).
   Единая палитра на страницу: подбери 2–3 цвета, выстави их в каждом блоке — так редактор и сайт
   не разойдутся.
4. **Проверяй контраст вычисленным цветом** (текст на фоне, автоконтраст кнопок), а не на глаз:
   у вендора есть и белый текст «по умолчанию», и белые подписи на светлых фонах.
5. **Свой HTML/CSS — только в крайнем случае** и осознанно: блок «Пользовательский код» (type 163)
   или `replace_form_html` расходится с настройками редактора и переживает ваши правки. Сначала
   исчерпай поля блока.
6. **Flex `1600` - не более 30% видимых блоков страницы по умолчанию.** Округляй лимит вниз,
   служебные виджеты не считай. Типы `167` и `3010` - обычные гибкие плитки и в лимит Flex не
   входят. Превышение допустимо только при обоснованной композиционной необходимости.

## Проверка результата

`status: OK` от конструктора не означает, что на сайте то, что нужно. Всегда проверяй вёрстку:

* `tobiz_verify_page` с `expect=[...]` — есть ли тексты в публичной вёрстке;
* `tobiz_page_summary` — состав блоков и порядок;
* `tobiz_get_computed_styles` - реальные шрифты, цвета, размеры и радиусы на desktop/mobile;
* `tobiz_diagnose_interactions` - формы, кнопки, ссылки и попапы без отправки заявок;
* `tobiz_screenshot_page` - полностраничные desktop/mobile PNG;
* `tobiz_audit_page` - все проверки выше плюс переполнение, изображения и JS-ошибки одной командой.

## Короткие рецепты

* **Собрать качественный черновик по брифу**: `tobiz_build_quality_page(apply=false)` выбирает
  проверенный шаблон, возвращает компактный рецепт и сгруппированный список фотослотов. Полный
  технический паспорт запрашивай только через `details=true`. Заполни `recipe`, укажи
  серую заглушку или реальные изображения и повтори с `apply=true`. Команда копирует структуру,
  сохраняет один раз и возвращает общий `quality_verdict` после desktop/mobile и editor-safe QA.
* **Собрать секцию**: `search_blocks` («тарифы», «обзор», «отзывы») → `describe_block` →
  `add_block` с `values` → `save_page` → `verify_page`.
* **Проверить ручное пересохранение**: перед открытием готовой страницы в визуальном редакторе
  вызови `tobiz_editor_roundtrip_check`. `save_blocked` запрещает пересохранение до исправления
  критичных блоков; `review` требует проверить предупреждения; только `editor_safe` означает,
  что штатный payload, порядок блоков и их cache собраны без критичных расхождений.
* **Поправить текст**: `list_blocks` → `get_block` (или `describe_block only=changed`) →
  `update_block` с новыми полями → `save_page`.
* **Прописать SEO**: `page_info` → `update_page(seo_title=…, seo_description=…, seo_keywords=…,
  og_image=…)` → проверить `<title>` и `meta` в публичной вёрстке.
* **Залить лого и подставить**: `upload_image(block_id=<реальный блок>, path=…)` → взять
  `filename` → `update_block`/`update_page(og_image=…)`.
* **Дублировать страницу**: `copy_page` (`apply=false` — сначала посмотреть план и доступные
  проекты) → `delete_page(confirm=true)` для уборки лишнего. **Внимание:** у копии новые
  `block_id`, поэтому анкоры меню и подвала нужно перевязать, а SEO и slug — перепрописать.
* **Собрать новую посадочную на своей площадке**: `copy_page` под тестовую страницу → переписать
  тексты в блоках (`update_block`) → `update_page` (slug + SEO) → `save_page` → `verify_page` →
  замеры в браузере (кнопки, отступы, мобильный вид).
* **Создать статью с фото и видео**: `create_article(fields={title, dir, description, ...})` →
  `upload_article_image` → `get_article`. Для видео передай HTML штатного `iframe` в
  `description`; результат появляется сразу.
* **Создать товар**: `create_product(fields={title, price, quantity, video1, ...})` →
  `upload_product_image` → `sort_product_images` → `create_product_offer` → `get_product`.
  Категории передаются полным списком `category_ids`.

## Экономия контекста

* `tobiz_page_summary` вместо `tobiz_list_blocks` — карта страницы вместо полных значений.
* `tobiz_describe_block(only="changed")` — только поля, отличающиеся от дефолта.
* `tobiz_search_blocks(limit=…)` — библиотека большая (162 типа), не выгружай её целиком.

## Если что-то сломалось

* `AUTH_FAILED` / `AUTH_CAPTCHA` — сессия конструктора недействительна; положи в том сессии
  файл `cookies.json` (достаточно пары cookie `session` + `email`) или задай `TOBIZ_EMAIL`
  и `TOBIZ_PASSWORD`.
* `RENDER_FAILED` — блок не отрендерился; проверь `type_id` и значения полей (частая причина —
  значение не из списка допустимых).
* `UPSTREAM_UNAVAILABLE` — конструктор не ответил; повтори запрос, черновик в памяти сохраняется.
